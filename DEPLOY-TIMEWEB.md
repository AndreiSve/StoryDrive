# Развёртывание StoryDrive на Timeweb Cloud

## 1. Создайте PostgreSQL

1. В панели Timeweb Cloud откройте **Базы данных** → **Создать** → **PostgreSQL**.
2. Выберите тот же регион, в котором будет приложение.
3. Сохраните хост, порт, имя базы, пользователя и пароль.
4. Если используете публичное подключение, включите защищённое подключение TLS.

Таблицы создавать вручную не нужно: StoryDrive применит идемпотентную миграцию при первом старте.

## 2. Создайте приложение из Git

1. Откройте **App Platform** → **Создать**.
2. Выберите тип **Dockerfile**.
3. Подключите GitHub/GitLab/Bitbucket и выберите этот репозиторий либо укажите его URL.
4. Выберите ветку `main` и оставьте включённым автодеплой по последнему коммиту.
5. Если `Dockerfile` находится в корне репозитория, оставьте путь к директории проекта пустым.
6. Укажите путь проверки состояния: `/health`.

Dockerfile содержит `EXPOSE 8080`, поэтому App Platform определит порт автоматически.

## 3. Добавьте переменные окружения

В настройках приложения добавьте:

| Переменная | Значение |
|---|---|
| `NODE_ENV` | `production` |
| `PORT` | `8080` |
| `DATABASE_URL` | `postgresql://USER:PASSWORD@HOST:PORT/DATABASE` |
| `DATABASE_SSL` | `require` для публичного TLS или `disable` для приватной сети без TLS |
| `DATABASE_POOL_SIZE` | `10` |

Если в пароле есть `@`, `:`, `/`, `?` или `#`, закодируйте пароль для URL. Например, `@` превращается в `%40`.

Для строгой проверки TLS добавьте `DATABASE_CA_BASE64`: это содержимое CA-сертификата, закодированное Base64. При наличии этой переменной сервер включает проверку сертификата.

## 4. Запустите и проверьте

1. Нажмите **Запустить деплой**.
2. Дождитесь успешной сборки и запуска.
3. Откройте технический домен из вкладки **Дашборд**.
4. Зарегистрируйте тестовый аккаунт.
5. Добавьте ссылку на свой XML-фид MaxPoster, обновите страницу и войдите снова — ссылка на фид должна восстановиться.

Техническая проверка:

```text
https://ВАШ-ДОМЕН/health
```

Ответ должен быть `{"status":"ok","service":"storydrive"}`.

## 5. Подключите домен

Привяжите свой домен на вкладке настроек приложения. TLS-сертификат для веб-приложения App Platform выпускает автоматически. После этого проверьте регистрацию и вход уже на основном домене.

## Обновления

При включённом автодеплое каждый `git push` в `main` запускает новую сборку. Пользователи и фиды не потеряются, потому что хранятся во внешней PostgreSQL, а не внутри контейнера.

## Если деплой не стартует

- `Переменная DATABASE_URL не задана` — добавьте строку подключения в App Platform.
- `certificate verify failed` — проверьте `DATABASE_SSL` и CA-сертификат.
- `password authentication failed` — перепроверьте пользователя/пароль и URL-кодирование пароля.
- `/health` отвечает, а регистрация нет — приложение запущено, но нет подключения к PostgreSQL; откройте логи деплоя.
